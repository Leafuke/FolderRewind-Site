# FolderRewind 1.9.3

Official website and documentation: https://folderrewind.top/

FolderRewind 1.9.3 is the **first public release of the 1.9 series**. It integrates **307 commits since v1.8.2**, including major work on the history and branching model, Plugin API 3, game-save discovery and onboarding, together with extensive reliability improvements across backup, restore, cloud synchronization, installation and application lifecycle management.

This release bundles **MineRewind 1.9.5**. The plugin development baseline is **Plugin API 3.6**, with `FolderRewind.Plugin.Abstractions` version **3.6.0**.

## ✨ Highlights

### New history, branches and checkpoints

1. **Rebuilt history core**
   - Replaces the legacy history implementation with an immutable model based on Commit Packs, Checkpoints, Branches and Representations.
   - History can distinguish sources, backup runs, branches and actual restorability more accurately.
   - Derived indexes can be rebuilt from durable data, with stronger repair and interrupted-operation recovery.

2. **A complete branch workflow**
   - Maintain independent branches for individual folder sources.
   - Browse history by source or backup run.
   - Create and manage checkpoints.
   - Use **Quick Restore** for straightforward recovery or **Checkout** for explicit history-state switching.
   - Checkout protects uncommitted working state before destructive branch changes.
   - Improved handling of multiple tips and workspace history anchors.

3. **Branch Merge**
   - Adds durable, conservative **file-level branch merging**.
   - Automatically handles changes with a safe deterministic result and exposes explicit resolution for conflicts.
   - Merge sessions, decisions and prepared results survive application restarts.
   - Strengthens Exact Representation validation, common-ancestor lookup and post-commit recovery boundaries.
   - Required cloud replicas can be prepared explicitly; Apply never silently downloads missing payloads.
   - Improves handling of long paths, encrypted archives, empty directory trees, damaged replicas and valid fallback replicas.
   - A merged history tip remains eligible for Exact Restore.

4. **History transfer**
   - Adds `.frhistory` import and export.
   - Improves history repository binding, repair and transfer.

After upgrading, review the in-app **migration report** and verify important history and backups before removing legacy data.

### 💾 Backup and restore

- Precisely select directories, individual files and glob patterns for backup.
- Edit the backup scope of existing sources.
- Improve source-scope preview and diff calculation.
- Consolidate configuration-level backups into atomic transactions.
- Adopt immutable rolling Copy-on-Write behavior for relevant backup paths.
- Prevent dangerous overlap between backup sources and destinations.
- Strengthen failure, cancellation, compensation and terminal-state handling.
- Rebuild Restore and Checkout around Version / Representation semantics.
- Preserve the complete current directory state during Safe Restore staging.
- Add per-operation forced-preservation paths for files and directories.
- Make cancellation semantics consistent across manual backup, automation and cloud synchronization.

### 🎮 Game-save discovery and onboarding

- Introduces a unified Discovery Provider architecture.
- Adds game-save discovery using **Ludusavi** rules.
- Detects installations from Steam, GOG and Epic.
- Allows plugins to participate in discovery and provider-targeted Backup Presets.
- Redesigns the discovery flow into clearer discovery, review and configuration-creation stages.
- Preserves manual configuration changes where possible during rediscovery.
- Runs scanning, rule verification and hashing in the background without blocking the main UI.
- Releases discovery resources when leaving the page.
- Reads Ludusavi rules per game and streams manifest download / compilation to reduce peak memory use.
- Adds transactional project creation, first-backup handling and partial-failure retry to onboarding.
- Adds cloud recovery previews and Minecraft environment diagnostics.
- Expands guided rclone / OpenList cloud setup.
- Adds OpenList executable-path and service-address configuration under Environment settings.
- Adds game-oriented performance presets including high-speed and space-saving profiles.

### 🧩 Plugin API 3

FolderRewind 1.9 contains a major plugin-system redesign.

- Public contracts now live in the standalone `FolderRewind.Plugin.Abstractions` package instead of requiring plugins to reference the application or UI projects.
- The SDK targets `net10.0`.
- FolderRewind 1.9.3 uses **Plugin API 3.6 / Abstractions 3.6.0**.
- Adds transactional plugin activation, deactivation and draining.
- Isolates plugin-private assembly dependencies.
- Adds typed settings validation and transactional settings updates.
- Host capabilities are exposed according to each plugin's declared requirements.
- Package installation, update and removal use stronger state tracking and recovery.
- Candidates are validated before activation.
- Updates use known-good rollback semantics if activation or migration fails.
- Legacy 1.8.2-style flat plugin payloads are migrated through a dedicated quarantine and recovery flow instead of being allowed to execute after a failed migration.
- Extends plugin support for configuration reconciliation, batch configuration creation, Backup / Restore, History, Artifacts, game discovery, Backup Presets, KnotLink, version metadata and per-operation preservation options.

Plugin API 3 extensions still execute inside the FolderRewind process. Host-service declarations are compatibility and disclosure mechanisms rather than an OS security sandbox, so only trusted plugins should be installed.

### ⛏️ Bundled MineRewind 1.9.5

- Targets Plugin API 3.6.
- Improves discovery across multiple Minecraft Java launchers.
- Adds Minecraft Bedrock save discovery.
- Improves region / scoped backup support.
- Expands player-data preservation options.
- Improves KnotLink current-world routing, command coordination and capability discovery.
- Tightens metadata boundaries between ordinary folders and Minecraft worlds.
- The package bundled with FolderRewind is byte-aligned with the final published MineRewind 1.9.5 package and verified by SHA-256.

### ☁️ Cloud synchronization

- Rebuilds history synchronization around Replica, Artifact and Commit Pack concepts.
- Supports Commit Pack union synchronization and history-fork detection.
- Allows required remote replicas to be explicitly prepared for Merge.
- Improves cancellation, retry and resource cleanup during history uploads.
- Strengthens consistency between local and cloud history state.

### 🖥️ UI, performance and reliability

- Improves asynchronous configuration saves and rollback on failure.
- Limits page caching and fixes duplicate activation lifecycle problems.
- Eliminates duplicate log appends and uses incremental log trimming.
- Improves history controls, Merge status, diagnostics and operation feedback.
- Adapts Merge dialogs to different available window sizes.
- Fixes default theme behavior and title-bar theme synchronization.
- Restores high-contrast behavior and improves accessibility labels and automation IDs.
- Removes additional hard-coded UI strings and completes localization / regional date handling.
- Improves tray-window foreground activation.
- Enforces single-instance behavior across release formats and brings the existing window forward on a second launch.
- Repairs taskbar icons and shortcut identity after Explorer / taskbar restarts.
- Uses streaming and atomic operations for large metadata files.
- Converts more scanning, history and background work to genuinely cancellable asynchronous flows.
