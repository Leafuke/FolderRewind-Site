# 备份模式详解

FolderRewind 基于 7-Zip 引擎提供三种核心备份模式：**全量**、**智能增量**、**覆写**。

:::caution 升级兼容性提示
如果你是从更早版本升级而来，请先用测试数据重新验证备份链和还原结果，再继续生产使用。
:::

## 先看结论

- 新手默认：**全量备份** + 开启“无变更时跳过备份”。
- 日常高频：**智能增量** + **链长上限** + **安全删除**。
- 临时快速更新：**覆写备份**（只维护最近一个包）。

## 备份模式对比

| 模式 | 说明 | 优势 | 适用场景 |
|------|------|------|---------|
| **全量备份 (Full)** | 每次生成一个完整新包 | 结构直观，还原稳定 | 新手、关键里程碑 |
| **智能增量 (Incremental/Smart)** | 仅打包变更文件，形成改进的增量链 | 速度快、占用低 | 大目录高频备份 |
| **覆写备份 (Overwrite)** | 更新最近备份包，不持续新增历史包 | 节省空间，操作简单 | 临时同步、缓存型目录 |

:::note 说明
当前产品文案中的“智能增量”对应代码中的 Incremental/Smart 语义。

不同版本间，增量链的生成、截断与还原细节可能调整，因此升级旧配置后建议重新做一轮验证。
:::

## 如何设置备份模式

1. 进入目标配置的 **配置设置**。
2. 打开 **备份策略**。
3. 在 **备份模式** 下拉框中选择：
	- 全量备份（每次生成新文件）
	- 智能增量（仅备份变更文件）
	- 覆写备份（更新最近的备份）
4. 点击保存并执行一次手动备份验证。

## 选择建议

- **Minecraft 存档：** 智能增量（高频、体量大时更省空间）
- **工作文档/项目：** 智能增量或全量（看磁盘与恢复偏好）
- **重要资料归档：** 全量 + 加密配置
- **临时目录/缓存目录：** 覆写备份

## 与模式强相关的关键参数

在“配置设置 → 备份策略”中建议同时关注：

- **无变更时跳过备份**：避免产生无意义备份。
- **保留最近备份数**：`0` 表示不限制。
- **智能备份链长度上限**：仅对智能增量有意义；达到阈值后会触发一次全量截断链条。

**链长截断的具体行为：**

当智能增量链中的备份数量达到 `MaxSmartBackupsPerFull`（默认 5）时，下一次备份会自动切换为全量备份（Full），形成新的基线。旧链不会被删除，但新备份不再依赖它们。

这样做的好处是：
- 控制还原链的长度，避免还原时需要合并太多增量包
- 限制单个增量链断裂的影响范围

- **安全删除**：清理增量链时尽量避免链断裂导致不可还原。
- **远程强制完整备份**：在联动场景中，可通过远程命令临时绕过当前模式，直接执行一次 Full 备份。

## 压缩与性能建议

FolderRewind 使用 7z/zip，可调压缩等级、算法和线程数：

- **压缩等级**：越高体积越小，但更慢。
- **CPU 线程数**：`0` 表示自动；性能不足时可限制线程。
- **文件类型规则**：可对 `*.zip`、`*.mp4` 等已压缩文件设置较低压缩等级，减少耗时。
  - 注意：启用文件类型规则后，7z 的 **solid 压缩**会被自动禁用。这是因为 solid 压缩要求所有文件使用相同的压缩设置，而文件类型规则允许不同文件使用不同等级。
- **低优先级压缩**：开启 `RunCompressionAtLowPriority` 后，压缩进程的 CPU 优先级会被降低，避免在备份时影响其他正在进行的任务。

### 性能预设（1.8）

性能预设会同时设置压缩线程数和进程优先级：

| 预设 | CPU 线程数 | 低优先级 | 适用场景 |
|------|------------|----------|----------|
| **自动** | `0`，由 7-Zip 自动决定 | 否 | 默认选择，优先完成速度 |
| **轻量** | 逻辑处理器数量的一半，最少 1 | 是 | 备份期间继续日常工作 |
| **极轻量** | 最多 2，且至少 1 | 是 | 前台应用或游戏对响应速度敏感 |
| **自定义** | 保留手动设置 | 保留手动设置 | 已经过基准测试的专用配置 |

处理器数量不同，轻量预设得到的实际线程数也会不同。切换预设后应保存配置，再通过一次真实备份观察耗时、CPU 占用和压缩体积。

### 高级 7-Zip 参数

1.8 允许为高级场景追加 7-Zip 参数。这些参数**只用于创建或更新备份包**，不会传给测试、列出、解压或还原操作。

为了保护 FolderRewind 对命令和输出的控制，以下类别会被拒绝：

- 裸操作命令 `a`、`u`。
- `@listfile` 一类外部列表文件。
- 改变操作、归档格式或压缩核心设置的参数，如 `-t`、`-mx`、`-m0`、`-mmt`。
- 密码、头部加密、输出目录和交互确认，如 `-p`、`-mhe`、`-o`、`-y`。
- 改变进度输出、包含/排除或输入来源的参数，如 `-bsp`、`-x`、`-i`。
- 未闭合的引号或其他无法可靠解析的输入。

配置会在保存时校验，执行备份前也会再次校验；无效参数会拒绝操作，而不会带着部分参数继续运行。不要直接粘贴来源不明的命令行。每次修改后都应先用测试目录创建备份并验证还原。

## 部分备份的还原规则

备份范围不是整个源目录时，备份包不具备清空目标后重建完整目录的能力。例如 [Minecraft 指定区域备份](/docs/guides/minecraft/selected-region-backup)：

- 普通还原与热还原都强制使用 **Overwrite（覆写）**。
- **Clean（清空后还原）** 会被禁用，避免删除未备份的文件。
- 包内文件会写回目标，但包外内容不会被同步到同一历史时间点。

在生产数据上启用任何部分备份前，请用副本验证备份清单、覆盖行为及应用程序自身的一致性。部分备份适合缩小保护范围，不等同于完整灾难恢复方案。

## 首次选型建议（可直接照抄）

- 通用办公：全量 + 无变更跳过 + 保留 30
- 开发项目：智能增量 + 链长上限 20 + 安全删除 + 保留 60
- 大型游戏存档：智能增量 + 无变更跳过 + 自动化任务 + 定期验证还原
