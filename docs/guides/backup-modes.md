# 备份模式与保留数量

首次备份使用 Full；日常频繁保存可以选择 Smart 或 Rolling。三种模式都保留版本历史，区别在于归档方式、依赖和空间成本。

![项目设置的“资源”页：每来源保留数量、立即清理和报告。](/img/docs/v1-9-6/retention-detail-zh-light-1305.webp)

*项目设置的“资源”页：每来源保留数量、立即清理和报告。 界面版本：1.9.6。*

## 选择模式

| 模式 | 工作方式 | 适用场景 |
| --- | --- | --- |
| Full | 完整保存有效受管范围，形成独立归档 | 首次备份、重要节点、升级后建立新基线 |
| Smart | 保存相对基线的新增、修改和删除，依赖完整基线及增量链 | 文件较多、每次变化较少的资料 |
| Rolling | 根据可信基线生成新的完整状态归档，保留原有归档 | 希望复用基线处理并保持版本历史 |

Rolling 不覆盖上一份归档；基线不可用时可回退 Full。旧配置中的 Incremental 对应 Smart，旧备份模式 Overwrite 对应 Rolling。还原页面的 Overwrite 则表示覆盖还原。

## 设置与验证

在项目设置的备份策略中选择模式、压缩格式和备份位置。Full 的“完整”指该来源的受管范围；过滤掉的内容不在备份中。

Smart 链长上限默认 5，达到阈值时创建新的 Full 基线。“无变化时跳过”可能使一次运行不产生新版本。切换模式后，用测试文件检查新增、修改和删除的还原结果。

## 保留最近 N 个版本

1.9.4 起，保留数量按**每个来源最近 N 个可恢复版本**计算；设为 **0** 表示无限保留。受保护版本额外保留，所以实际数量可能更多。

自动清理只有在可以净释放空间时执行。重建增量链需要临时空间，若清理反而增加占用，自动策略会跳过。不要在资源管理器中手动删除 Smart 依赖包。

## 手动清理与报告

![手动清理报告：本地归档、实际空间变化与各来源结果。](/img/docs/v1-9-6/cleanup-zh-light-1604.webp)

*手动清理报告：本地归档、实际空间变化与各来源结果。*

在项目设置中执行立即清理，查看各来源的处理结果。需要优先达到保留数量时，可选择对应选项，但这可能增加磁盘占用。

数量清理处理本地归档，保留逻辑历史与云端副本。删除单个历史节点前，查看影响预览；应用可重建依赖以保留后续版本的恢复能力。详见[历史管理](/docs/guides/history-timeline)。

## 压缩与部分备份

线程数 0 表示自动选择；轻量预设限制到约半数逻辑处理器，极轻量最多 2 个。文件类型压缩规则会禁用 solid；高级 7-Zip 参数受应用限制，不能覆盖输出、来源、密码或进度控制。

区域等部分备份始终使用 Overwrite 还原，即使归档本身可精确读取，也不会清空未捕获的内容。
