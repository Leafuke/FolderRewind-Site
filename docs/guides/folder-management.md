# 来源管理、重命名与历史绑定

## 添加与范围

在配置管理添加单目录、子目录或审阅发现资源。每个受管来源保持稳定ID，路径和显示名称不替代身份。编辑SourceScope的All／Include并查看有效文件预览；来源与归档目标重叠会阻断。

## 重命名

打开来源操作菜单的重命名，查看预览的源目录、备份目录、相关本地元数据与配置／自动化引用，确认冲突后执行事务。操作失败会尝试回滚；若回滚也失败，先核对路径／配置一致性，暂停新备份还原。

不能承诺重命名会改写不可变旧历史或所有云对象。旧Version／Source身份和保存的Replica定位仍是历史事实；现有云对象不随本地名字物理改名。按实际本地定位修复／更新检查结果，不在资源管理器随意批量改档名。

## 历史来源绑定

还原／Checkout旧Checkpoint缺少当前来源时，用户确认路径后按原稳定Source身份补回绑定。一次性导出到新目录与恢复历史Source绑定不同；不能仅同名就建立绑定。

## 验证

检查新旧路径、配置范围、自动化目标、旧版本可物化性和新备份祖先；云用户验证旧／新副本。批量发现保持用户审阅权，防止上游重扫覆盖手工编辑。

## 保存失败后的处理

1.9.3 的交互式配置更改使用异步保存并在失败时回滚。等待保存结果，核对错误信息与重新加载后的路径、范围和身份；不要把尚未落盘的界面输入当成已生效配置。保留错误日志，修复权限或磁盘问题后重新保存。
