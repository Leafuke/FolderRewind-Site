# Minecraft 世界合并

分支可以让你分别尝试建筑、地形改造或不同玩法。需要把两个分支的成果放到一起时，在合并工作页选择 MineRewind 的 Minecraft 语义合并，按世界和区块处理变更。

## 准备两侧版本

先启用 MineRewind，为 Java 世界建立完整备份和分支。在高级历史中选好目标分支与来源分支，准备共同祖先及两侧需要的本地归档。

打开[合并工作页](/docs/guides/history-branches)，为本次会话选择 Minecraft 语义合并及策略。默认合并方式为文件合并；语义合并可以直接用于常规世界备份，实验性语义备份开关保持原设置即可。

## 选择合并策略

| 策略 | 如何组合世界数据 | 适合的情况 |
| --- | --- | --- |
| 保守策略 | 按区块组件组处理变更；普通实体变化等情况会要求整个世界各维度统一选择一侧 | 希望明确审阅世界状态与实体关系 |
| 地形优先 | 按区块合并地形和 POI，所有维度的普通实体沿用目标分支；含内嵌实体的区块及其 POI 也沿用目标侧 | 主要合并建筑或地形，并准备检查实体位置 |

两种策略都会处理已知的计时、缓存和待执行更新差异。地形优先完成后，请重点检查生物、载具等实体与新地形的位置关系。

## 在地图中处理冲突

1. 阅读分析结果，按世界、维度和变更类别定位需要处理的区域。
2. 在地图与列表之间选择区块，查看共同祖先、当前侧和来源侧的差异。
3. 按当前项目允许的选项选择保留哪一侧；处理整世界选择时，检查所有维度。
4. 打开结果审阅，确认最终文件及仍需处理的问题，再应用到目标分支。

遇到格式或覆盖范围诊断时，先按提示准备完整输入或选择相应侧。待处理的阻断项清除后，应用操作才会开放。

## 应用后检查

应用前确认当前工作已有备份或安全快照。应用会完成暂存、构建与验证，并在实际写入时协调游戏状态。离开页面后，可以重新打开保存的合并会话继续处理。

完成后检查目标分支、历史版本和世界内容。建议先在复制的世界中检查建筑边缘、跨区块结构、实体、POI 与各维度，再继续日常游戏。

地图浏览与历史版本对比见[世界地图预览](/docs/guides/minecraft/world-preview)。
