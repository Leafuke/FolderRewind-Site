# 来源范围、过滤与还原白名单

## 顺序与保护边界

SourceScope先限定每个来源的All／相对Include globs。配置过滤和提供器文件策略／范围随后收窄；不能把配置白名单当作扩大来源硬边界的方式。预览有效受管文件集合，核对发现资源与手动编辑范围。

## 备份黑白名单

黑名单模式排除匹配项，白名单模式只包含匹配项。按当前设置使用名称／相对路径／通配符和启用的regex规则。精确目录、glob与regex口径不同；先用正反样例检查，避免宽泛路径误包含／误排除。

插件必要规则仍参与有效边界；区域范围不能把未受管源扩进来。临时远程backup_blacklist追加去重，空值不清除；backup_whitelist非空追加并选白名单，不替换成独立无约束范围。

## Clean与还原白名单

Clean只修改受管边界内数据。还原白名单保留匹配当前路径，但备份同路径内容存在时以备份为准；不是永久保护当前文件免受归档覆盖。Overwrite不清空未包含内容；部分捕获强制Overwrite。

普通还原保留产生的派生内容可能让Workspace baseline为Derived。Checkout／Merge有自己的精确目标和协调语义，不把普通还原白名单／玩家保留当分支切换机制。

## 验证

建立边界内／边界外、匹配／不匹配、同路径冲突和新文件样例，备份检查包清单，再Clean／Overwrite还原比较字节。修改范围或上游发现结果先审阅再保存，不仅凭匹配数量判断安全。

## 单次文件与目录强保留

KnotLink `restore_preserve_paths`／SDK `RestoreRequestOptions.RestorePreservePaths` 只影响本次普通还原，不修改持久过滤规则。使用相对文件路径，目录以 `/` 结尾；多个项目以逗号分隔，不使用 glob、绝对路径或 `..`。当前文件字节优先，当前缺失的目标文件保持缺失，所选目录中的新增和删除也按当前状态保留。

最多 16 个选择器；暂存合计最多 4096 个文件操作、64 MiB 当前字节。必须在有效受管边界内。Minecraft 路径相对于唯一受管世界根，无法唯一识别世界时拒绝。范围与大小不满足时操作失败，不静默忽略。Checkout／Merge 不使用此覆盖。
