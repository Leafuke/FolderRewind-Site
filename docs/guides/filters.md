# 来源范围、过滤与还原保留

想跳过缓存、只备份文档，或在还原时保留当前文件，可以分别设置来源范围、备份过滤和还原保留规则。

![过滤规则可选择作用于文件、文件夹或两者。](/img/docs/v1-10-0/filters-110-zh-light-1604.webp)

## 先确定来源范围

在来源设置中选择全部内容，或使用相对 Include 规则。项目的黑白名单和插件规则会在这个范围内继续筛选。打开有效文件预览，核对最终将备份的文件，再保存设置。

## 选择规则作用对象

每条规则可以匹配文件、文件夹或两者。匹配到文件夹时，规则会作用于该目录及全部子项。

| 规则示例 | 作用对象 | 黑名单中的效果 |
| --- | --- | --- |
| `*.tmp` | 文件 | 排除各层目录中名称匹配的临时文件 |
| `cache` | 文件夹 | 排除名为 cache 的目录及其中全部内容 |
| `./build` | 文件夹 | 排除来源根下的 build 目录及子项 |
| `logs/**` | 文件 | 排除 logs 下匹配的文件 |
| `cache` | 两者 | 排除同名文件，或同名目录及其子项 |

只有名称的规则按名称匹配；带路径的规则相对来源根解析。`*` 匹配当前路径段，`**` 可以跨目录，`?` 匹配单个字符。需要正则时先启用正则选项，再使用 `regex:` 前缀，并用有效文件预览检查结果。

黑名单排除匹配内容，白名单只保留匹配内容。已有旧规则保持原匹配方式；编辑规则或更换作用对象后，按界面重新预览。

## 还原白名单

还原白名单用于保留 Clean 清理阶段匹配的当前路径。归档中存在同路径文件时，会写入备份内容。Overwrite 会保留归档未覆盖的当前内容；区域备份等部分捕获使用 Overwrite。

## 单次文件与目录强保留 {/* #restore-preserve-paths */}

通过 KnotLink 的 `restore_preserve_paths` 或 SDK 的 `RestoreRequestOptions.RestorePreservePaths`，可以为一次普通还原选择当前优先的文件或目录。

```text
notes.txt,config/
```

使用来源相对路径，目录以 `/` 结尾，多个选择用逗号分隔。所选文件保留当前字节，当前已经删除的文件保持删除；目录内的新增和删除也保留当前状态。

每次最多 16 个选择器，暂存最多 4096 个文件操作、64 MiB 当前内容。选择范围限定在有效受管边界内；Minecraft 路径相对唯一受管世界根。使用明确文件或目录路径即可，范围表达式留给备份过滤。

这些保留选项用于普通 Restore 和 Quick Restore。Checkout 与 Merge 按所选分支或合并结果处理。规则设置完成后，可用新增、修改、删除三个小样例测试一次还原。
