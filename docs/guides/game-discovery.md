# 自动发现游戏存档 Beta



## 发现什么

游戏定义是目录知识，不证明安装；安装证据来自 Windows Steam／GOG／Epic。Ludusavi主清单、用户手选次级清单和本地覆盖提供资源规则。注册表资源可显示为不支持，不承诺注册表备份；Heroic／Lutris不在当前 Windows Beta 范围。

打开 Beta 页面不会自动联网，下载／更新清单需明确操作。选择扫描根、商店／账号与输入清单，手动扫描后阅读逐根诊断；网络失败可使用有效缓存，损坏输入不能当正常空结果。

## 审阅与创建

结果按游戏展示，可有多个 provider 的多个 Backup Set。配置草稿由用户选择资源和预设后产生，不把检测游戏直接当已创建配置。MineRewind多个实例可建立独立配置。

Steam默认选择最近账号；其他账号／通配回退可见但未选。确认资源、路径、范围和危险广根提示；目标与来源重叠会阻断。保存是一次事务，失败保留原配置和审阅基线。

## 来源范围

每个 SourceScope 是 All 或受校验的相对 Include globs，支持目录、文件集合及精确范围。配置黑／白名单和插件策略只能缩小硬边界。来源边界内的完整捕获不等于整个物理根。

## 再发现

三方审阅比较上次完成审阅的 upstream baseline、当前用户配置和最新候选，默认保留用户更改。provider + DefinitionId + SetId 是发现集合身份；显示名不是身份。上游增删改、保护范围收缩和冲突需要审阅，不悄悄覆盖用户配置。

## 验收

用测试存档验证扫描、账号选择、确认创建、来源范围编辑、单来源备份、再发现冲突和取消。检查 Ludusavi／PCGamingWiki 归属说明；清单知识与运行期 Kind 所有权不同。

## 1.9.3 的分阶段确认

扫描结束后先按游戏／备份集合确认配置，再逐项确认来源与资源；阅读完整路径、版别、提供器和范围，不将游戏条目直接当成已保存配置。选择结果后继续设置名称、备份位置并审阅。扫描期间相关选择操作禁用；取消或离页后旧扫描结果不会继续更新当前页面。

Minecraft 创建入口可直接“自动发现存档”，无需先选目录或下载 Ludusavi。自动发现包括已知启动器位置和记住的根；“选择目录扫描”仅检查指定范围，再次自动发现才合并已知位置。Java 与 Bedrock 使用各自的 Kind，按草稿实际版别确认。发现以目录和 `level.dat` 为线索，不证明世界健康或游戏可加载。
