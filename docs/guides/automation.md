# 自动化备份任务

## 开始前

先验证手动备份、来源范围和还原，再在配置设置的自动化区启用。自动任务仍受配置操作门、插件就绪性和取消生命周期约束，不应与同来源的外部写入器或另一安装渠道混用。

## 触发与目标

支持间隔分钟、月／日／时／分计划、启动时、选定来源、文件解锁条件和连续无变更停止。计划月／日0表示每月／每天；间隔按保存的有效范围设置。一次触发可记录逐来源结果及Run，不保证每次都产生Checkpoint。

条件FileUnlocked使用来源相对路径，检测从锁定到释放的转变，不因持续解锁反复触发。Minecraft示例使用session.lock；不要沿用level.dat“必定被锁定”的假设。条件文件须由实际程序以可检测方式锁定。

## 无变更与保留

连续无变更达到阈值可关闭自动化，有变化重置计数；检查状态后手动重新开启。KeepCount治理Checkpoint，Pins／分支／Workspace／恢复点和依赖可能保留更多。Smart链限与Full基线不代替恢复验证。

## 云与诊断

备份完成后云传输是单独阶段；本地成功不等于云已完成。区分NoChanges、SuccessWithWarnings、Blocked、取消和失败。Require一致性不可用时应阻断，Prefer降级要保留诊断。

测试启动、间隔、跨计划时间、来源选择、锁释放、无变更停止、取消以及忙碌操作；最后再投入无人值守。

## 取消与结果核对

已完成的本地备份与后续云传输分别记录；取消云上传不会把已完成的本地备份改成未成功。检查各来源结果和任务终态，再决定重试范围。首次使用向导启动的备份进入全局任务，离开页面不会取消已开始的备份；取消应从任务入口操作。
