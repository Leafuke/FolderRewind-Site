# 自动化备份任务

自动备份适合定期保存已经验证过的项目。在项目设置的“自动化”中选择触发方式，并确认要备份的来源。

![展开自动化选项的演示草稿；截图后已放弃修改，未启动长期任务。](/img/docs/v1-9-6/automation-zh-light-1604.webp)

*展开自动化选项的演示草稿；截图后已放弃修改，未启动长期任务。 界面版本：1.9.6。*

## 选择触发方式

| 方式 | 使用场景 | 设置时检查 |
| --- | --- | --- |
| 间隔 | 工作期间持续保存 | 间隔分钟数及选定来源 |
| 计划 | 固定时间执行 | 月、日、时、分；月或日为 0 表示每月或每天 |
| 启动时 | 打开应用后保存一次 | 启动后任务结果与来源状态 |
| 文件解锁 | 等程序完成写入后备份 | 来源相对路径，以及真实的锁定到释放过程 |

文件解锁条件只响应锁定到释放的转变，不会因文件一直未锁定而重复触发。Minecraft 通常检查 `session.lock`；是否可检测仍取决于实际游戏行为。

## 保存设置并观察一次运行

先确认手动备份和还原可用，再保存自动化设置。检查任务页中的来源、触发时间和最终结果；无变化时跳过可能不会创建新版本。

连续无变化达到设定阈值时，可自动停止任务；有变化会重置计数。任务停止后，确认原因再手动开启。保留数量按每个来源的最近可恢复版本计算，受保护版本额外保留，见[保留策略](/docs/guides/backup-modes)。

## 云上传与取消

备份后上传是独立阶段。本地备份完成后取消云传输，不会撤销已经完成的本地备份。阅读各来源结果和任务状态，再决定重试哪一部分。

创建向导启动的首次备份进入全局任务；离开页面不会取消它，需要从任务入口取消。其他自动任务也应等待取消完成后，再执行同项目操作。

## 排查未触发或被阻止

检查自动化是否开启、来源选择是否正确、时间计划是否匹配，以及插件和一致性要求是否满足。`Require` 无法满足时会阻止备份；`Prefer` 降级时应阅读警告。文件解锁未触发时，先确认程序确实以可检测方式锁定该文件。
