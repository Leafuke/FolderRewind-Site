# 从云端恢复到新目录

换电脑或本地归档丢失时，可以从云端找回已有备份。从首页“新建备份项目”的下拉菜单选择“从云副本还原到新位置”，选择连接和目录，再挑选要恢复的项目与版本。

![从云端恢复入口选择接入方式，再按向导准备连接。](/img/docs/v1-10-0/cloud-recovery-110-zh-light-1604.webp)

## 1. 准备连接

准备 rclone，选择本次使用的配置文件和 remote，填写存放 FolderRewind 云备份的目录。可以复用已有 WebDAV、OneDrive、S3 或 OpenList 连接；连接准备见[云存档](/docs/guides/cloud-archive)。

这个恢复入口按只读方式访问云端。连接仅用于本次检查与恢复，原项目的账号、目录和云配置保持原状。

## 2. 查找项目与版本

点击“查找云端备份项目”，选择项目，再读取历史版本。列表使用云端 Native History 中的项目和来源身份；名称相近时，可以展开详情核对 ID。

选择所需版本，查看可恢复状态、所需数据及诊断。Smart 和插件增量表示需要完整依赖；使用插件格式时，先启用对应的物化插件。加密备份需要原密码。

## 3. 选择新的本地目录

指定新的恢复位置，检查磁盘空间，并阅读确认摘要中的版本、云目录和本地路径。选择一个与现有来源分开的目录，方便检查恢复结果。

确认后，应用下载所需备份数据，验证大小、哈希和依赖，再将内容物化到新目录。任务结束后打开该目录，检查文件；Minecraft 世界可复制到测试实例中加载。

## 继续使用恢复的数据

新目录恢复保留原来源及其活动分支状态。需要把恢复的数据作为新的日常备份来源时，检查内容后再创建项目；需要接续原项目时，按[数据迁移](/docs/guides/data-migration)导入配置、历史并确认路径。

已有项目更换账号或远端目录后，也可以使用“重连原仓库并只读取回历史”，确认原项目 ID，再取回对应历史。

## 处理连接与数据问题

| 提示或现象 | 下一步 |
| --- | --- |
| 找不到项目 | 核对 remote 和根目录，选择包含 `_folderrewind` 数据的实际备份位置 |
| 需要重新授权 | 返回连接设置完成授权，再重新读取目录 |
| 缺少归档或依赖 | 检查原设备上传结果，补齐所选版本的完整依赖 |
| 插件格式不可用 | 启用匹配的插件，再重新检查版本 |
| 下载或校验失败 | 查看任务日志，核对远端副本后重试 |

取消时等待当前任务结束，再开始下一次恢复。已保留的原始云备份可继续用于后续重试。
