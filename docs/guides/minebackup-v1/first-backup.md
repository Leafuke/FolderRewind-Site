# 首次备份

首次备份的目标是验证一条完整链路：来源目录可读、备份根目录可写、压缩程序可执行、历史记录可保存，最后生成的归档可以被还原。

## 推荐操作

1. 在主界面选中目标世界。
2. 保持备份模式为 `Full`。
3. 输入可选注释，例如 `baseline_20260806`。
4. 触发备份并等待任务完成。
5. 打开历史记录和备份目录检查结果。

首次不要同时测试 Smart、自动化、云同步和热联动，否则失败时很难区分是基础配置还是外部依赖的问题。

## 程序会做什么

备份任务通常会依次完成：

- 检查配置、世界路径、目标目录和压缩工具。
- 扫描变化并应用黑名单规则。
- 根据模式决定 Full、Smart 或 Overwrite 归档流程。
- 必要时执行迁移检查、快照或热备份协同。
- 写入归档、历史记录和 Smart 链元数据。
- 应用保留数量和安全删除策略。
- 如果配置启用了云归档，再由独立云任务同步结果。

## 结果检查

备份成功后至少确认以下项目：

- 备份根目录的目标世界子目录出现新的归档文件。
- 历史记录显示新的时间、类型、注释和文件状态。
- `_metadata/<世界名>/state.json` 和对应 `records` 信息没有明显错误（Smart 模式尤其重要）。
- 归档文件不是 0 KB，也没有小到明显不可能包含目标数据。
- 日志中没有压缩工具非零退出、路径不可写或文件无法读取的错误。

如果开启 `skipIfUnchanged`，第二次对完全未变化的世界执行备份可能不会新增归档；这属于预期行为，应在日志和历史记录中确认“跳过”原因，而不是反复点击。

## 首次失败的处理顺序

1. 先检查 7-Zip 路径和日志中的退出码。
2. 再检查源目录、备份目录和快照目录的权限及剩余空间。
3. 暂时关闭复杂黑名单，回到一个世界、Full 模式的最小配置。
4. 退出游戏后再测试一次普通备份。
5. 普通备份成功后，再单独验证热备份、Smart 或云任务。

如果迁移状态为 Degraded 或 Failed，程序可能主动强制建立新的 Full 链。这是为了避免沿用不完整的旧元数据，不应通过手动复制文件绕过。

## 备份后的两个动作

- 在历史记录中写下可读注释，并给关键节点标记为重要。
- 立刻在测试目录执行一次还原，确认“备份成功”不仅代表文件写入成功，也代表恢复链可用。

完成这次验证后，再阅读[备份模式、链完整性与安全删除](/docs/guides/minebackup-v1/backup-modes)和[首次还原](/docs/guides/minebackup-v1/first-restore)。
