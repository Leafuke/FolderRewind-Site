# 首次还原

第一次还原必须在测试世界或副本目录中完成。还原会改变目标目录，运行中的世界还可能继续写入文件；不要把第一次演练放在唯一的生产存档上。

## 标准流程

1. 确认目标世界已经退出，或明确使用热还原流程。
2. 打开历史记录，选择一个已确认存在的归档。
3. 阅读归档类型、注释、时间和本地/云端状态。
4. 选择还原方式并确认是否在还原前备份。
5. 等待任务完成后检查日志和历史记录。
6. 重新打开测试世界，验证关键文件和游戏状态。

## 四种还原方式

| 方式 | 行为 | 适用场景 |
| --- | --- | --- |
| `Clean` | 清理目标目录后再恢复；还原白名单中的内容会被保留 | 想让目标尽量回到完整归档状态 |
| `Overwrite` | 直接覆盖归档中的内容，不主动删除归档没有的额外文件 | 常规覆盖、部分归档或不确定时的保守选择 |
| `Reverse` | 找到选定时间点之后的 Smart 变化并反向应用 | 从较新的状态退回某个 Smart 节点的特定场景 |
| `Custom` | 只提取输入列表中的文件或目录 | 修复 `level.dat`、区域文件或单个配置 |

Custom 列表使用逗号分隔；如果希望提取整个目录，可以按界面提示在目录名后使用 `*`。第一次还原建议先使用 `Clean` 或 `Overwrite`，不要直接用 Reverse。

## 还原前备份

开启 `backupBefore` 后，程序会先对当前目标建立兜底备份，再执行还原。生产世界建议保持开启，尤其是在使用 Clean、Reverse 或自定义列表之前。

如果当前世界仍被占用，普通还原可能会被阻止。不要用任务管理器强制结束游戏来“释放文件”；先正常保存并退出，或者按[热备份与快照机制](/docs/guides/minebackup-v1/hot-backup)和 [KnotLink v2 联动](/docs/guides/minebackup-v1/knotlink-integration) 的流程完成协同退出。

## 部分归档的安全边界

如果归档只包含源目录的一部分，Clean 没有能力用包外信息重建完整目标。此时应优先使用 Overwrite；对于需要确认的危险 Clean 场景，MineBackup 会要求额外确认或直接拒绝。

同样，运行中世界的外部自定义归档不能被当作安全的热还原输入。需要热还原时，应先确认当前世界、联动版本和归档来源都满足条件。

## 成功标准

- 目标目录中的关键文件恢复到预期时间点。
- 游戏可以正常读取世界，且没有明显的残留写入或损坏。
- 历史记录仍能看到还原前后状态。
- 还原前兜底备份在需要时可以再次选中。

如果结果不符合预期，停止继续操作，先恢复还原前备份，再更换明确的目标归档或还原方式。不要在同一个异常目标上连续覆盖多个归档。
