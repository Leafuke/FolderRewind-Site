# 创建第一套配置

MineBackup 把每个备份任务组织成一套独立的普通配置。配置包含来源世界、备份根目录、压缩参数、备份模式、过滤规则、保留策略和可选的云/热备份设置。

如果同时使用多个启动器或实例，建议让每套配置只对应一个存档根目录，避免同名世界互相覆盖。

## 第一步：定位存档根目录

存档根目录是包含目标世界文件夹的父目录，而不是某一个世界本身。

![存档路径演示](/img/docs/guides/minebackup-v1/where-folder-saves.gif)

常见示例：

- Java 版常见路径：`%APPDATA%\\.minecraft\\saves`
- Windows 基岩版通常位于包目录下的 `games\\com.mojang\\minecraftWorlds`，实际文件夹名可能不直观。
- 第三方启动器可以从启动器的“打开存档文件夹”功能复制路径。

![基岩版存档名称演示](/img/docs/guides/minebackup-v1/where-bedrock-saves.jpg)

向导支持自动选择常见 Java/基岩版路径，也可以点击文件夹选择器手动指定。只要目标是普通文件夹，MineBackup 也可以备份非 Minecraft 数据。

![PCL2寻存档](/img/docs/guides/minebackup-v1/pcl-to-find.gif)

完成选择后执行扫描，确认至少有一个目标世界，并检查世界名称和描述是否正确。

## 第二步：指定备份根目录

备份根目录用于保存每个世界的归档和内部元数据：

- 尽量使用另一块物理磁盘或外置设备。
- 不要让备份根目录落在源世界目录内部，避免备份再次被备份。
- 确认目录长期可写，且保留策略不会误删唯一的恢复点。

MineBackup 会按世界建立归档子目录，并在备份根目录的 `_metadata` 区域维护 Smart 链需要的状态和记录。

## 第三步：配置压缩与性能

配置设置中可以选择：

- 归档格式：`7z` 或 `zip`。
- 压缩方法：`LZMA2`、`Deflate`、`BZip2` 或 `zstd`。
- 压缩等级：范围随方法变化，等级越高通常越慢。
- CPU 线程数：`0` 表示交给压缩工具自动决定。
- 低优先级压缩：减少备份对前台游戏或其他程序的影响。

第一次运行建议保留默认方法和中等等级。先验证归档能还原，再根据磁盘、CPU 和耗时调整。

## 关键配置项

| 配置项 | 作用 |
| --- | --- |
| `saveRoot` | 世界或源文件夹的父目录 |
| `worlds` | 被管理世界的名称和描述 |
| `backupPath` | 归档和备份元数据的根目录 |
| `zipPath` | 用户指定的压缩程序路径，可留空让程序探测 |
| `zipFormat` / `zipMethod` / `zipLevel` | 归档格式、压缩方法和等级 |
| `backupMode` | Full、Smart 或 Overwrite |
| `keepCount` | 自动保留的备份数量；`0` 表示不限制数量 |
| `skipIfUnchanged` | 没有变化时跳过重复备份 |
| `maxSmartBackupsPerFull` | Smart 链达到该数量后建立新的 Full 基线 |
| `backupBefore` | 还原前先建立兜底备份 |
| `blacklist` | 备份阶段排除匹配的文件或目录 |
| `snapshotPath` | 热备份使用的快照目录 |

配置会生成稳定的 `ConfigId`，外部联动和便携配置使用它识别配置，不应依赖会变化的列表序号。

## 推荐的第一套参数

- 备份模式：`Full`
- 无变化时跳过：开启
- 保留数量：按磁盘空间设置，例如 30
- 压缩方法和等级：先使用默认值
- 还原前备份：生产世界建议开启
- 过滤器：先不加复杂规则

这套参数的目标是先建立可验证的基线。Smart、自动化、云归档和热备份都应在基线成功后逐项启用。

## 多配置与待绑定配置

推荐按启动器、整合包、用途或实例拆分配置。例如，正式生存档和实验世界不要共用一套容易误选的规则。

从云端 `portable-config.json` 导入的新配置可能处于 **Pending Local Binding** 状态。必须先绑定本机的存档根目录、备份根目录和压缩工具；绑定完成前，程序不会允许备份、还原、删除、云写入或自动任务。

## 完成标准

- 扫描结果至少包含一个正确的世界。
- `backupPath` 可写且与源目录规划合理。
- 7-Zip 探测成功。
- 保存配置后重启程序，配置仍然存在。
- 下一步可以执行[首次备份](/docs/guides/minebackup-v1/first-backup)。
