# 过滤规则

MineBackup 1.16.1 的配置级备份过滤以 **黑名单** 为主；还原阶段另有用于 Clean 清理步骤的**还原白名单**。它没有把 FolderRewind 的备份白名单模式直接带入 MineBackup 配置。

## 备份黑名单

黑名单在扫描和打包阶段生效，匹配的文件或目录不会进入新的归档。适合排除：

- 可重新生成的缓存。
- 运行日志和临时文件。
- 不需要纳入恢复点的下载或构建产物。

不要为了缩小体积而排除 `level.dat`、世界数据、关键配置或 Smart 链依赖文件。规则应从少量、明确的项目开始。

## 规则匹配方式

源码中的路径规则会统一大小写和斜杠，并支持以下形式：

- 文件名匹配，例如 `latest.log`。
- 相对路径或目录段匹配，例如 `cache` 或 `logs/server`。
- 绝对路径匹配；路径迁移时会尝试按原始根目录映射。
- 以 `regex:` 开头的 ECMAScript 正则表达式，按不区分大小写处理。

无效的正则会被忽略并记录兼容行为，不应把“规则被保存”理解为“规则一定生效”。MineBackup 的规则不是任意 7-Zip 命令参数，也不要把 `*`、`?` 等 shell 通配符默认当成独立匹配语法。

## 还原白名单

还原白名单只影响 `Clean` 还原开始前的删除阶段：匹配的文件或目录会被保留，不会因为它们不在目标归档中而被清理。

它不表示“只从归档中提取这些文件”，也不会改变 Overwrite 或 Custom 的提取列表。需要只恢复指定内容时，请使用[首次还原](/docs/guides/minebackup-v1/first-restore)中的 `Custom` 方式。

常见用途：

- 保留本机私有配置。
- 保留环境差异文件。
- 保留不属于备份范围、但不能被 Clean 删除的目录。

## 安全验证流程

1. 在测试配置中新增一条规则。
2. 先查看备份日志和归档清单，确认关键文件仍在。
3. 在副本目录执行 Overwrite 或 Clean 还原，比较包外文件的处理结果。
4. 连续两次结果正确后，再应用到生产配置。

如果规则过宽，优先删除或收窄规则，不要叠加更多例外来掩盖不清晰的路径范围。
