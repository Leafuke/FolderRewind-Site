# 云归档

MineBackup 的云归档由 rclone 执行传输，MineBackup 负责配置、队列、历史分析、元数据关联和安全提示。云归档是本地备份的补充，不是本地验证的替代品。

## 前置条件

1. 先完成一套本地备份—还原闭环。
2. 准备可写的 rclone 路径、远端路径和工作目录。
3. 确认远端账号已经在 rclone 中完成配置。
4. 在设置页启用云同步。

rclone 不随 MineBackup 程序包分发。设置页可以在用户确认后下载固定版本的受管理 rclone，并在安装前后检查 SHA-256 和 `rclone version`。MineBackup 不会复制、解析或上传用户的 rclone 凭据文件。

## 两种同步模式

| 模式 | 同步内容 | 适用场景 |
| --- | --- | --- |
| 仅历史 | 配置档可分析的历史和状态信息 | 先在另一台机器重建历史索引 |
| 历史 + 备份包 | 历史、归档文件以及相关 metadata | 需要异地恢复完整备份链 |

设置中还可以控制：

- 上传后是否同步历史。
- 还原前是否自动尝试下载缺失归档。
- 单次命令超时（默认模型为 600 秒）和重试次数。
- 云任务的工作目录和上次退出状态。

## 配置远端

在目标配置的云同步设置中填写：

- rclone 可执行文件路径，或使用受管理版本。
- 远端路径。
- 云命令工作目录。
- 同步模式、超时和重试策略。

远端路径会按配置和世界建立安全的路径段。不要把本地凭据、访问令牌或完整 rclone 配置内容粘贴到普通任务命令或文档注释中。

## 历史页的单条操作

每条历史记录可以根据状态执行：

- 上传归档及相关 metadata。
- 从云端下载本地缺失的归档。
- 查看是否存在云端副本。

上传通常优先处理归档，再同步 `state` 和 `record` metadata。归档成功但 metadata 部分失败时，历史会提示部分同步；Smart 链必须补齐元数据后才能作为完整恢复链使用。

对“仅云端副本”执行还原前：

1. 在历史页下载归档。
2. 确认本地文件状态变为可用。
3. 检查 Smart 链和 metadata。
4. 再执行还原。

## 云端配置交换

`portable-config.json` 只交换明确允许的字段，并使用稳定 `ConfigId` 合并。它可以包含配置名称、逻辑世界定义、压缩/备份/保留设置、黑名单和可迁移云策略。

以下内容不会被上传或导入覆盖：

- 本机存档、备份和快照路径。
- 压缩程序、rclone 和字体路径。
- 凭据、命令、脚本和自动化任务。
- Special Config、Service Mode 兼容字段和运行结果。

从云端新增到本机的配置会处于 Pending Local Binding，必须手动绑定本地路径和工具后才能执行危险或自动化操作。

## 故障排查

- 云按钮灰色：检查配置是否启用、归档是否存在、rclone 是否可执行。
- 历史可导入但归档下载失败：检查远端路径映射、工作目录和权限。
- 提示 metadata 部分同步：先补同步，再验证 Smart 链，不要直接删除本地基线。
- 超时或重试耗尽：保留本地归档，查看日志中的退出码和远端错误。

第一次上线时完整演练：本地 Full → 上传 → 云端分析/下载 → 本地还原。确认成功后再把云同步接到自动化任务。
