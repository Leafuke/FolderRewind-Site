# 自动化任务

自动化适合“重复执行同一套已验证流程”。请先用普通配置手动完成一次备份和还原，再启用长期任务。

## 普通配置的自动触发

普通配置可以启用游戏会话开始时备份。MineBackup 通过检测世界文件的占用状态判断游戏会话开始和结束：

- 新世界从未被检测为占用时，开始事件可以触发 `backupOnGameStart`。
- 世界结束时，程序可以根据全局“退出时停止自动备份”设置停止相关自动任务。
- 这不是“应用程序启动后立即备份”；它针对被检测到的世界会话。

第一次启用时，建议只选择一个世界，并观察一次开始、备份和退出日志。

## 统一任务系统

MineBackup 1.16 的统一任务模型包含：

| 维度 | 选项 |
| --- | --- |
| 类型 | Backup、Command、Script |
| 执行模式 | Sequential、Parallel |
| 触发方式 | Once、Interval、Scheduled |
| 备份目标 | 配置和世界索引 |
| 命令任务 | 命令文本和工作目录 |

`Script` 当前仍是未实现的扩展项，设置页不会把它当作可执行脚本启用。Command 任务会调用平台命令解释器，不能假设同一条命令跨 Windows、Linux 和 macOS 可移植。

统一任务数据模型还保留重试、超时、完成通知和错误通知等高级字段；实际可以编辑的字段以当前版本设置页为准，不要在没有对应控件或日志证据时假设程序会自动重试失败任务。

## 触发方式

- **Once**：启动一次任务，适合手动编排或迁移后的单次验证。
- **Interval**：按分钟周期运行，最小间隔受界面校验约束。
- **Scheduled**：按月、日、时、分运行；月或日为 0 表示每月或每天。

计划任务按本地时间计算。跨时区、夏令时或机器休眠后，应该查看下一次实际触发日志，而不是只根据配置文字推断。

## 顺序与并行

- **Sequential**：等待前一个任务完成后再运行，适合多个任务共享磁盘或存在先后依赖。
- **Parallel**：与相邻任务并行，适合来源和目标完全独立且磁盘/CPU 资源充足的任务。

不要让两个任务同时修改同一个世界或同一个配置档。MineBackup 的资源协调可以阻止部分冲突，但并行配置仍会增加空间、CPU 和外部命令竞争。

## 上线前检查

1. 手动执行同一世界的备份并确认历史记录可见。
2. 检查目标配置和世界索引没有因重排而失效。
3. 观察至少 2～3 个触发周期。
4. 确认失败时日志会给出原因，且不会无限制地重复破坏性操作。
5. 为自动任务设置合理的保留数量和 Smart 链长度。

如果任务没有触发，先检查启用状态、时间字段、目标索引和程序日志；不要一开始就增加更多并行任务。
