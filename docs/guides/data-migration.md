# 配置、历史与归档迁移

换电脑或切换安装渠道时，需要分别保留配置、历史和实际归档。只导出其中一类，不能保证另一台设备可以还原。

![配置与历史分别导出；原生历史导入采用合并去重。](/img/docs/v1-9-6/migration-detail-zh-light-1310.webp)

*配置与历史分别导出；原生历史导入采用合并去重。 界面版本：1.9.6。*

## 先准备三类资料

| 资料 | 包含什么 | 还需要什么 |
| --- | --- | --- |
| 配置导出 | 项目、来源和设置 | 新设备路径、插件和加密密码 |
| `.frhistory` | 仓库信息与不可变历史数据包 | 实际归档和全部依赖 |
| 归档或可信云副本 | 可恢复的文件内容 | 对应历史、来源绑定与解密材料 |

本机工作区、索引、副本定位和 DPAPI 密码材料有设备边界，不会因导出历史而全部搬迁。

## 导出与导入配置

以下流程适用于包含迁移事务修复的 1.9.x 构建；上方 1.9.6 截图仅用于定位设置入口。

退出旧客户端的自动任务并保存完整数据副本。在设置的“数据迁移”中导出配置；可使用本地 JSON 或经过验证的云连接。

导入时先预览项目名称、项目 ID、来源与备份路径，并选择“本机恢复”或“跨设备迁移”。目标端有匹配项目时默认本机恢复，否则默认跨设备迁移；两种模式都会检查实际状态。确认后只准备候选配置，当前配置仍在使用。可取消待生效导入，或选择“重启并应用配置”。重启会等待活动任务并保存最新原配置；新进程在服务初始化前切换，未完成的激活会恢复原配置。

导入项目保留原项目和来源身份，也保留原来的自动备份与云开关。迁移状态单独暂停各项目的相关操作，不会改写开关；通过批量检查并确认后，恢复已就绪功能。云连接未就绪不妨碍已确认的本地备份，其他未完成项目也不影响已完成项目。导入 `config.json` 不会使旧路径自动有效，也不会迁移本地密码存储。仅导入配置时，绑定的历史仓库可能尚未迁移；先导入对应历史，再完成项目设置。

## 导出与导入历史

导出默认采用“全部项目”，显示项目数量；选择“指定项目”后展开列表，可全选或清空。项目 ID 放在详情中。新版 v2 `.frhistory` 可包含多个项目；导入器继续读取 v1 单项目文件。无历史项目会显示为零，不会因为项目未被最近浏览而遗漏。绑定仓库缺失或损坏时，需要先处理该项目。

导入前检查原应用版本、迁移格式、项目与来源 ID、版本/分支/Pack 数量，以及目标端是否存在同 ID 项目。传输包包含清单、仓库描述符和不可变 Pack，`IncludesPayloads=false`，不携带归档、旧设备工作区或 SQLite 索引。

原生历史采用合并去重，不替换历史列表，也不改写 Pack 身份。每个项目独立提交；批次可以部分完成，按报告安全重试。提交已决定但需要恢复时，不要删除事务或 staging 目录。应用会在读取仓库前补齐未完成的 Pack 集合。

结果分别显示历史提交、项目关联、本机初始化和新增/重复 Pack 数量。找不到同 ID 项目时，历史等待原配置；请导入原配置，不要用同名但不同 ID 的新项目接管。

## 完成本机设置

“数据迁移”条目内集中显示状态、进度和按需操作。应用会自动批量检查，一次“检查并恢复已就绪项目”确认即可恢复选中的备份与云功能；只对异常项目打开路径设置，预览根目录替换（例如 `D:\Games` → `E:\Games`），或调整来源和备份目标。来源需可访问，目标需可写且不能与来源重叠；必要插件与加密密码需要在目标设备准备好。

缺失的工作区建立为 Unknown 基线，缺失的本地副本目录初始化为空；有效本机状态不会因历史导入被覆盖。本机恢复保留身份、路径和来源语义一致的有效分支、基线与副本状态，只重置变化的来源。跨设备迁移不能据旧设备提示猜测当前状态。损坏状态需要受控恢复，不能用初始化掩盖。

Unknown 状态下首次备份建立独立全量基线和新分支，不猜测旧电脑的活动分支或增量依赖；接续旧分支请使用 Checkout。本机恢复只复用目标端已有且匹配的云绑定，跨设备迁移需重新绑定。确认不会补跑启动备份或批量上传旧归档，原来关闭的开关仍保持关闭。

旧构建已将开关写成关闭时，应用不能猜测原设置。使用“从原配置读取原开关”选择原导出 JSON，仅恢复身份匹配项目的自动备份与云开关，不覆盖路径、规则或凭据；随后仍需确认运行许可。批量失败或取消保留已完成项目，剩余项目可重试。

## 搬迁归档并验证

迁移报告中的“本机状态有效”不表示旧版本已可还原。本轮迁移功能不新增备份载荷可用性检查，报告会明确显示“备份归档未验证”。

独立复制归档和增量依赖，或下载可信云副本。空副本目录不会自动识别复制来的归档，旧绝对路径也不会自动变成新设备定位。还原继续使用现有副本、依赖和安全检查；先用测试副本验证文件及应用加载，再启用自动化。验证前不要删除原设备数据。

云历史同步合并事实，不复制本机工作区，也不按设备时间覆盖另一端历史。

## 从 1.8 升级或回退

升级时先处理[旧备份接管报告](/docs/getting-started/v1-9-upgrade#193-旧历史接管报告)。删除边界未知的旧版本只使用覆盖还原或新目录恢复。回退到 1.8 使用升级前的独立副本，避免旧客户端修改 1.9 仓库。
