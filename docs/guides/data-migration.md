# 升级、配置与历史迁移

升级、换电脑或切换安装渠道时，先保留原数据，再按配置、历史和归档分别迁移。完成一次测试还原后，就可以继续日常备份。

## 先准备好资料

| 资料 | 如何准备 | 用途 |
| --- | --- | --- |
| 配置 | 在设置的“数据迁移”中导出 JSON，或使用已验证的云连接 | 带回项目、来源与备份策略 |
| 历史 | 导出 `.frhistory`，选择全部或指定项目 | 带回版本、分支和历史记录 |
| 归档 | 复制备份目录及完整增量依赖，或准备可信云副本 | 提供实际可恢复内容 |
| 密码与插件 | 单独记录加密密码，准备所需插件 | 在新环境中解密与读取备份格式 |

退出原客户端的自动任务，保留整个应用数据目录与归档目录的副本。安装渠道的数据位置见[安装指南](/docs/getting-started/installation#数据目录与安装渠道)。

## 导入配置并重启应用

在目标设备打开“数据迁移”，选择配置文件，预览项目、来源与备份路径。选择“本机恢复”或“跨设备迁移”；匹配原项目的本机恢复可以保留仍有效的分支与基线，跨设备迁移会重新检查本机环境。

确认后，应用先准备待生效配置。选择“重启并应用配置”完成切换；重启前仍可以取消导入。应用会等待活动任务，保存原配置并完成切换。

原有自动备份与云开关会随配置保留，迁移检查负责逐项恢复运行。需要找回旧构建关闭的开关时，可选择“从原配置读取原开关”，使用原导出 JSON。

## 导入历史

导入 `.frhistory`，核对项目 ID、来源、版本和分支。多项目文件可按项目处理，已有 Pack 会合并去重。每个项目分别显示历史提交、关联和本机初始化结果，部分完成的批次可以按报告重试。

历史包保存历史记录，归档按前面的资料清单另外准备。没有同 ID 项目时，先导入原配置，再检查历史关联。

## 完成本机设置

应用会批量检查迁入项目。在“数据迁移”条目中查看路径、插件、密码与云连接状态，选择“检查并恢复已就绪项目”。本地备份与云功能分别检查，已经就绪的项目可先恢复使用。

多个项目都从 `D:\Games` 搬到 `E:\Games` 时，使用“批量重定位路径”，预览并保存所选项目。其他项目可以单独调整来源与备份位置。来源需可访问，备份位置需可写，并与来源分别存放。

新设备上的首次备份会建立独立全量基线和新分支。希望继续原有分支时，从历史执行 Checkout。本机恢复会复用仍匹配的本机状态与云绑定；跨设备迁移需重新绑定云连接。

## 准备归档并测试还原

检查迁移报告中的归档验证状态。复制来的归档还需要有效的副本定位与完整依赖；云端数据可以按[云恢复指南](/docs/guides/cloud-recovery)准备。

选择测试目录恢复一份版本，核对文件内容与游戏加载结果，再启用自动化。检查完成前继续保留原设备的数据副本。本地密码材料使用 Windows 用户范围的 DPAPI，加密密码请按[加密指南](/docs/guides/encryption)准备。

## 接管旧版备份 {/* #legacy-upgrade */}

从 1.8 升级且仍保留旧归档时，在历史中打开旧备份接管报告：

1. 核对记录所属来源，为尚未分配的记录选择正确来源。
2. 指定归档的实际位置，补齐 Smart 元数据与增量依赖。
3. 保存并验证，根据报告处理缺失文件或身份问题。
4. 在测试目录还原，再创建一次新的 Full 备份作为当前分支基线。

删除范围缺少历史记录的旧版本会标记为受限恢复，可用 Overwrite 或恢复到新目录。新的完整基线就绪后，可以继续使用 Clean、分支切换和合并。

旧 v2 插件代码由迁移流程保留到隔离目录，相关功能使用兼容 v3 的插件。旧云连接需要重新准备，原远端和旧增量依赖继续保留。

## 回退与恢复

需要回退时，退出当前版本，使用升级前独立保存的配置、历史和归档副本。启动或迁移中断时，保留日志并进入恢复中心，按诊断完成剩余步骤。
