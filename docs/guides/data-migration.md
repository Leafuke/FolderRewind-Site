# 配置、历史与载荷迁移

迁移分三类：config.json配置、不可变历史事实、实际备份字节。导出任一类不代表另外两类已保存；本机Workspace／Replica Catalog及DPAPI密码也有设备边界。

## 配置

设置→数据迁移，选择配置导出／导入；可按界面选择本地JSON或经过验证的云连接。导入替换配置前先备份原数据和确认路径；配置不会自动迁移本地加密密码材料。空／损坏配置使用恢复中心，不删文件重试。

## 历史传输

历史导出使用 `.frhistory` ZIP传输容器，包含manifest、repository.json和packs；IncludesPayloads=false。当前导出以最后选择的历史配置为准，未选时采用首个配置；导出前先在历史打开所需配置，并核对传输manifest的ConfigId。

导入使用原生不可变事实合并与去重，不提供旧history.json替换列表语义；不兼容格式／哈希／身份拒绝。没有匹配的运行期配置时可形成孤立仓库，不自动创建完整来源配置。重复导入不会重复添加同Pack。

## 载荷与设备路径

独立复制归档或准备可信云副本及所有物化依赖，保留原始文件以便核对。只导入历史不会使旧绝对定位器自动变为新机器的有效本地副本；验证可用定位与来源绑定，必要时恢复到新目录后建立新配置。

## 顺序与验收

退出旧客户端→备份全部数据／归档→安装匹配渠道与版本→导入配置→导入各配置历史→准备载荷／依赖→确认来源路径、插件、加密和运行状态→测试还原／应用加载→恢复自动化。

云历史并集不搬本机Workspace，不按设备时间覆盖另一端历史。回退旧版使用升级前副本；不要将1.9生成的packs交给1.8改写。

## 从 1.8.2 接管

升级后先在历史打开旧备份接管报告，确认来源、归档定位和验证状态。已接管的旧版本仍可能具有未知删除边界，使用新目录恢复或不删除的 Overwrite；新的 Full 备份建立已知边界后再使用高级历史。详情见[升级报告流程](/docs/getting-started/v1-9-upgrade#193-旧历史接管报告)。旧云配置不会自动沿用，重新配置连接前保留原远端与 Smart 依赖。
