# 分支切换与文件级合并

## 创建与切换

在高级历史选定配置与可靠 Checkpoint 创建／命名分支。切换是 Checkout，不是单来源 Restore。查看来源映射，补齐历史来源在当前配置中的稳定身份绑定；路径需要用户确认。

默认先保护未提交工作，创建独立安全快照。缺少精确可物化闭包、目标不完整、路径冲突或恢复未完成时不执行切换。操作完成后 Workspace 记录活动分支与逐来源基线，为后续备份确定祖先。

## 分叉与合并

先准备两侧输入、共同祖先及所需云副本。选择目标分支／输入，计算文件级三方差异。无变化／可快进与真正冲突合并分别显示；有冲突时逐项选择文件版本或允许的解决方式，再重新计算和确认。

1.9首发采用保守文件级合并；Minecraft .mca、NBT、stats、advancements 是文件冲突，不承诺区块／NBT字段语义合并。不要把世界文件手工拼接当作受支持策略。

## 准备、应用与故障

解包、冲突解决、压缩、哈希和往返验证在环境协调之前完成。只有实际写入来源需外部退出／解锁，安全快照可扩大范围；零写入合并跳过游戏退出。

确认后 Host 在配置操作门内应用并原子提交。提交前失败与提交后故障不同；CommittedRecoveryRequired 说明已提交但恢复未结束，先看诊断并运行受控恢复，不再次点击应用或自动重进。

## 验证

在测试目录验证新建分支、双尖端、未提交保护、源路径映射、冲突、取消、重启恢复和字节级结果。成功后检查活动分支、Workspace、历史刷新与备份祖先，而非只看按钮成功提示。

## 与普通还原的区别

Checkout／Merge 不应用普通 Restore 的玩家保留、还原白名单或单次强保留。旧接管记录的删除边界未知时，先恢复到新目录或不删除的 Overwrite，再创建新的 Full 版本；不能把受限旧版本直接当作完整分支检查点。
