# 分支切换与合并

分支适合保留不同方案：一个分支继续日常工作，另一个尝试新的改动。在高级历史中，可以切换到某个分支，也可以把两侧变更合并到目标分支。

![合并工作页集中展示变更文件、文本差异和冲突选择。](/img/docs/v1-10-0/merge-110-zh-light-1604.webp)

## 创建与切换分支

在历史页选择项目和来源，打开高级视图，从完整可恢复版本创建并命名分支。每个来源分别管理自己的分支。

选择目标分支，检查来源路径和当前未提交的内容，再执行 Checkout。需要保留当前工作时，在确认界面选择保护方式，或先手动创建备份。切换后检查活动分支和文件内容；后续备份会沿该分支继续。

从旧版接管的备份可以先恢复到测试目录，再创建新的 Full 备份，作为日常分支操作的基线。具体步骤见[数据迁移](/docs/guides/data-migration#legacy-upgrade)。

## 打开合并工作页

选择当前目标分支和要合入的来源分支，准备共同祖先及两侧归档。工作页会列出文件变更、自动处理结果和需要决定的冲突。

文件合并为默认方式。Minecraft Java 世界还可为本次会话选择[语义合并](/docs/guides/minecraft/world-merge)，按世界与区块处理变更。

## 比较文本并选择结果

1. 从变更列表选择文件，在双栏视图阅读两侧文本差异。
2. 对冲突选择保留当前版本或来源版本，也可以按界面提供的选项选择删除等结果。
3. 需要自己整理文本时，在编辑器中处理好文件，再导入作为该项结果。
4. 同类冲突可以批量选择；完成后逐项复查重要文件。

未完成的合并会话会保存。离开页面后，从历史中的合并入口重新打开，继续处理剩余项目。

## 审阅与应用

打开结果审阅，检查最终会写入、替换和删除的文件。确认目标分支、当前路径和保护选项后再应用。

应用前的解包、构建和验证在暂存区域完成。真正写入来源时，应用协调外部程序并提交结果；只涉及历史推进的操作可直接完成。

完成后检查文件与目标分支的新历史。普通还原的白名单、玩家保留和单次强保留用于 Restore；分支操作按本次合并结果写入。

## 继续处理异常

归档缺失时，先准备本地或云端副本及其依赖。出现需要恢复的结果时，保存日志，按应用诊断完成恢复，再继续相关操作。可以先用两个小文本文件练习自动合并、冲突选择和重新打开会话。
