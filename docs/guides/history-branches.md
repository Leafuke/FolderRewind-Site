# 分支切换与文件级合并

分支适合保留不同方案的进度。还原找回一个版本，Checkout 切换到另一分支状态，Merge 将两侧文件变更合并到目标分支。

## 准备分支

在高级历史中选择项目、来源与完整可恢复版本，创建并命名分支。来源身份决定历史绑定，不能仅凭相同文件夹名替代。

从 1.8 迁移的旧备份如无法证明删除边界，先覆盖还原到测试目录并创建新的 Full 版本，再作为精确分支基线。

## 切换分支

选择目标分支，检查来源映射和实际路径，再执行 Checkout。当前未提交内容需要保护时，会按保护策略创建安全快照；确认窗口可能要求明确选择丢弃当前更改。缺失归档依赖、路径冲突或尚未结束的恢复状态会阻止操作。

切换完成后，检查活动分支和文件内容；后续备份沿切换后的来源基线继续。Checkout 不使用普通还原的玩家保留、白名单或单次强保留。

## 在合并工作页处理差异

1. 选择目标分支和另一侧输入，准备共同祖先以及需要的本地或云端归档。
2. 打开合并工作页，查看三方文件差异。无变化、快进和存在冲突的合并会分别提示。
3. 使用文本双栏比较阅读冲突；逐项选择结果，也可批量处理同类冲突。
4. 在应用前审阅最终文件结果，确认后执行。未完成的合并会话可以重新打开继续处理。

合并以文件为单位。Minecraft `.mca`、NBT、stats 和 advancements 不提供区块或字段语义合并；选择某一侧文件不代表已合并其中所有游戏数据。

## 检查结果与处理失败

解包、冲突决策、压缩和验证先在暂存区域完成。真正写入来源前才协调外部程序；零写入合并可跳过游戏退出。

完成后检查目标分支、历史记录和实际文件。出现 `CommittedRecoveryRequired` 表示提交已发生但后续恢复未完成，保留诊断并运行受控恢复，不再次点击应用或自动重进游戏。

建议用两个小文本文件练习：在两侧修改不同文件，确认自动合并；再修改同一文件，确认冲突选择和取消、重开会话的行为。
