# 安全快照与恢复点

安全快照是破坏性历史操作前的精确、分支独立恢复点，不推进活动分支；不能与临时 staging 或普通自动备份混为一谈。

## 使用

Checkout／Merge／受控还原的确认界面检查未提交工作与保护选项。保护捕获失败时停止操作，不把失败快照视作已保护。完成后在高级历史的恢复点入口查看并确认其配置范围与来源。

## 恢复与释放

选择恢复点，核对 Checkpoint 和来源路径，准备完整依赖后通过 Host 恢复。恢复不是直接拷贝临时目录。保留的快照保护其物化依赖，保留数量可能超过 KeepCount。

确认不再需要且其他保护满足后显式释放恢复点；释放不等于立刻删除全部逻辑历史或共享载荷，Host 保留策略仍计算其他依赖。

## 故障

RecoveryRequired／CommittedRecoveryRequired、源目录占用或载荷缺失时先看诊断，禁止重复破坏性写入。测试重启后仍可查看、准备、恢复和释放快照，再用于重要项目。

## 受限旧历史

旧接管版本的载荷验证不能证明历史删除边界。受限恢复和安全恢复点是不同概念：报告允许新目录恢复或不删除的 Overwrite，并不自动授予 Clean、Checkout 或 Merge 权限。升级后用新的 Full 备份建立可靠基线。
