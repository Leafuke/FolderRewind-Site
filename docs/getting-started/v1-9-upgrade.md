# 1.9 升级、迁移与恢复

从 1.8 升级时，1.9 会迁移配置、旧备份历史和插件数据。1.9.6 改善了旧 Smart 元数据读取、验证结果保存和快速还原。

## 升级前准备

退出应用及自动任务，备份整个应用数据目录和归档目录，记录安装渠道、来源路径、插件版本及加密密码。单独复制 `config.json` 不包含归档，也不能跨设备迁移 Windows DPAPI 密码材料。

保留原始副本，安装[适合设备的版本](/docs/getting-started/installation)。商店与 Setup 使用不同的数据目录；切换渠道需另按[迁移指南](/docs/guides/data-migration)操作。

## 检查配置与插件

升级后检查项目、来源范围和目标路径。旧 v2 插件代码进入隔离目录，不直接加载；内置 MineRewind 可迁移对应数据，其他插件需安装兼容 v3 的版本。确认插件实际运行状态，再启用相关任务。

旧 Smart 与 Overwrite 的数值由迁移处理；新的 Rolling 创建不可变归档，不覆盖旧包。不要手工替换配置枚举或删除隔离目录。

## 查看旧备份接管报告 {/* #193-旧历史接管报告 */}

在历史中选择对应项目，从迁移提示或更多操作打开报告：

1. 核对每条记录所属来源；未分配的记录选择正确来源。
2. 为找不到的归档指定实际保留路径。Smart 还需完整依赖和元数据。
3. 保存更改并执行验证，按诊断处理缺失依赖、损坏文件或身份问题。
4. 在测试目录还原，检查新增、修改和删除的结果。

`RestrictedReady` 表示验证通过但恢复范围受限：无法证明旧备份的删除边界，只能覆盖还原或恢复到新目录。文件与目录类型冲突仍会阻止操作。先创建新的 Full 备份，再使用 Clean、Checkout 和 Merge。

1.9.6 可保留有效验证结果；归档或元数据变化后会要求重新验证。修改来源和归档定位后，报告与历史列表会刷新。关闭提示只保存本机提示偏好，并不代表迁移完成。

## 验证后恢复日常任务

检查一次 Full、Smart 或 Rolling 备份及还原，再恢复自动化。来源没有活动分支时，快速还原可选择最近可恢复旧备份；已有分支时仍按活动分支解析。

旧云配置与旧云归档不会自动迁入新历史。保留远端资料，重新创建连接，并准备旧 Smart 依赖。

## 需要回退时

退出新版，使用升级前独立保存的配置、历史与归档副本。不要让 1.8 客户端继续写入 1.9 的历史仓库。启动或迁移失败时保留诊断并使用恢复中心，避免删除数据文件后反复启动。
