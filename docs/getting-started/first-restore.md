# 首次还原

## 选择目标

在配置管理打开历史，选择来源版本或配置Checkpoint。先用测试副本练习；确认配置、来源、路径、时间、范围和结果。目标必须有可恢复表示及依赖，不仅是列表记录。

## 准备与确认

若副本仅在云端，先预览并准备所需依赖，验证大小／哈希。检查来源映射及外部程序写入；Minecraft必须完成所需协调。输入正确加密密码，缺少提供器／来源或恢复状态异常时先修复。

## 模式

- Clean：将有效受管边界内内容恢复为目标状态；不要理解为清空整个物理根。
- Overwrite：覆盖捕获中的文件，不删除捕获之外内容；可能保留更晚的数据。
- 部分捕获：始终Overwrite，即使表示能Exact物化。

还原白名单保留匹配的当前内容，但归档提供同路径内容时归档优先。Safe Restore／还原前备份与模式不同，按确认对话框核对保护选项；不是所有“成功还原”都自动包含独立长期保护点。

## 结果与恢复

等待任务终态，逐项比较文件和应用加载。NoChanges表示无需修改；SuccessWithWarnings阅读警告。RecoveryRequired／CommittedRecoveryRequired先看诊断和受控恢复，不重复破坏性操作。

Quick Restore恢复活动分支唯一尖端，不保证上一时间点；分支切换与合并另见[高级历史](/docs/guides/history-branches)。有玩家保留或白名单派生内容的普通还原可能形成Derived baseline。

验证之后再用于正式资料。缺失本地载荷先检查可信云副本，不按旧教程盲目清除失效历史。

## 保留与旧历史核对

需要保留当前文件而不是恢复其归档版本时，使用本次普通还原的强保留参数，见[过滤与强保留](/docs/guides/filters#单次文件与目录强保留)。它也保留当前删除状态，与还原白名单不同。旧迁移版本如提示未知删除边界，应选择不删除的 Overwrite 或新目录恢复；先完成新的 Full 备份再使用 Clean／高级历史。
