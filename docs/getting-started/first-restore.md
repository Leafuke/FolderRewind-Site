# 首次还原

用首次备份的测试文件夹练习一次还原，你就能熟悉如何找回旧内容，以及当前文件会如何变化。

## 1. 选择历史版本

打开历史，选择项目和来源，找到“初始版本”。核对时间、备份范围和可还原状态，再选择还原。归档在云端时，先准备所选版本及完整依赖；也可以使用[从云端恢复到新目录](/docs/guides/cloud-recovery)。

## 2. 检查目录与保护选项

确认目标路径，让正在使用该目录的程序完成写入。加密归档需要原密码；Minecraft 热还原还会协调游戏状态。

![在确认窗口检查还原方式与还原前备份选项。](/img/docs/v1-9-6/restore-detail-zh-light-710.webp)

需要保留当前工作时，检查“还原前备份”选项，或先手动创建一个版本。分支切换和合并的保护方式见[安全快照](/docs/guides/safety-snapshots)。

## 3. 选择还原方式

| 方式 | 文件变化 |
| --- | --- |
| Clean | 恢复受管范围内的目标状态，删除该范围内多出的内容 |
| Overwrite | 写入备份中的文件，保留其余当前内容 |
| 部分备份或受限旧备份 | 使用 Overwrite，保留备份范围以外的数据 |

还原白名单用于保留清理阶段的当前路径，同路径文件仍使用备份内容。需要当前内容优先时，可以使用[单次强保留](/docs/guides/filters#restore-preserve-paths)。

## 4. 执行与检查

确认后等待任务完成，打开文件检查内容，观察新增、修改和删除样例的结果。游戏存档还可以在复制的测试实例中加载。

从[通知中心](/docs/guides/notifications)查看警告和操作日志。需要恢复处理时，按诊断完成恢复，再继续操作该项目。

## 快速还原与分支

快速还原使用活动分支的唯一尖端版本；来源尚无活动分支时，可以选择最近可恢复的旧备份。想回到更早时间，直接在历史中指定版本。

尝试不同方案时，可以创建[分支并切换或合并](/docs/guides/history-branches)。普通还原的玩家保留、白名单和强保留按 Restore 流程使用。
