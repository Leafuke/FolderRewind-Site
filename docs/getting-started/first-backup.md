# 首次备份

![普通文件夹三步创建入口，1.9.2.0／API3.5 中文候选版；尚未提交来源](/img/docs/v1-9/creation-candidate.png)

*普通文件夹三步创建入口，1.9.2.0／API3.5 中文候选版；尚未提交来源.*


## 准备测试来源

建立只含测试文件的目录，选择与来源不重叠的独立备份目标，确认权限与空间。不要把来源放入备份目录或把目标放在来源中；重叠会阻断。

## 创建备份项目

首页选择新建，按当前创建流程填写名称、项目种类、来源和目标，检查摘要后完成事务。也可从模板、Minecraft引导或插件批量发现／游戏发现Beta创建；发现只生成草稿，核对保护边界后提交。

专用Kind需要兼容且Active的插件。加密配置需按界面设置并妥善保存密码。创建成功后进入管理页；添加来源时选择目录／子目录，核对稳定身份、来源范围及有效文件预览。

## 执行

设置Full作为第一轮，核对过滤和压缩后备份单来源或全部来源。填写本次操作备注，查看任务进度和最终结果。一次配置调用可记录逐来源结果，不能把一个来源成功当全部成功。

## 验证

历史按来源版本或运行查看，检查结果、Checkpoint及可还原性。修改／新增／删除测试文件，执行备份并按[首次还原](/docs/getting-started/first-restore)验证目标内容。颜色与包大小不证明完整性。

在设置运行核心自动校验，它会使用测试配置验证关键行为；仍需验证你的实际范围、加密和游戏加载。完成后再选择Smart／Rolling、自动化或云上传。
